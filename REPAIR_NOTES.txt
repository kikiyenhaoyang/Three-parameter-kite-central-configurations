run_all 套件修復說明

已確認的阻擋原因
1. run_all.m 在第 26 行先呼叫 check_bundle_files，通過後才處理 Only、List、CheckOnly。
2. 依附件原樣放在同一資料夾，若 Symbolic Math Toolbox 和 JVM 可用，完整性檢查的第一個錯誤會是 Missing bundle file: README.md，因為附件名稱是 README(3).md。
3. 即使恢復所有檔名，原 SHA256SUMS 共 32 筆中，仍有 16 個檔案沒有附上，另有 5 個現有檔案的 SHA-256 不符。11 個檔案符合原校驗碼。
4. 五個不符檔案：README.md、manifest.json、reference_expected.json、run_all.m、selftest.m。這表示校驗清單與附件內容不一致；不能僅由雜湊判定修改原因。
5. 原清單包含 certify_regular_mass_zero_boundary.m（B1）和 reference_logs 等缺少的檔案。附上的 manifest 只有 K0、N1、K1、K2、S1、R1、R2、R3 八項，沒有 B1，因此 README 的 B1 呼叫範例也不適用。

修正內容
- 恢復 README、兩個 MATLAB 函式及兩個 JSON 憑證的標準檔名。
- 八支驗證程式、兩個憑證 JSON、arithmetic_reference.json、reference_expected.json 均保持附件原始位元組。
- run_all.m 和 selftest.m 只修正文案註解，執行程式碼完全不變。
- 更正 README 的 B1、九項驗證及參考結果數量說明。
- manifest 仍列出原有八項，版本標成 2.3.0+attachment-repair.1。
- 為這份重整後套件重新建立 SHA256SUMS，保留檔案完整性檢查。
- 原始校驗清單保存在 ORIGINAL_SHA256SUMS.txt，各筆比對結果在 repair_audit.json。

執行方式
將 ZIP 解壓到新資料夾，MATLAB 的 Current Folder 切到包含 run_all.m 的 kite_bundle_repaired 資料夾。
先執行：
    run_all('CheckOnly', true)
    run_all('Only', {'K0'})
確認後再執行：
    run_all
若需要額外算術測試與五份既有參考結果比對，可改執行：
    selftest('Full', true)

環境與限制
原 README 指定 MATLAB R2020b 或更新版本及 Symbolic Math Toolbox；run_all 也需要 JVM。
本次環境沒有 MATLAB，僅核對檔案、雜湊、manifest 依賴與函式名稱，未執行 MATLAB，也未宣稱數學驗證全部通過。
重新產生的校驗碼代表這份重整後套件的位元組，並不證明缺少的原始完整套件已恢復。B1 不包含在內。
若畫面已顯示 RUN 某項後長時間沒有更新，run_all 使用 evalc 收集輸出，會等該項完成才寫入日誌；S1、R1、R3 等大量精確符號運算可能耗時。
若仍報錯，保留完整紅字錯誤及其前面的 RUN 訊息，以區分環境、路徑或驗證運算的問題。
